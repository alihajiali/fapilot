# Deployment and operations

[Documentation index](index.md)

## Prepare configuration

Run the application from its project root so `config`, `apps`, `.env`, and relative
SQLite paths resolve consistently. Use a tested, locked dependency set and an
explicit Python version. The generated project dependency and Dockerfile use unpinned
Fapilot; adapt them before a reproducible release.

For environment-driven deployments, remove conflicting literal settings from
`config/settings.py` as described in [configuration](configuration.md). Supply
`DEBUG=false`, a nonplaceholder `SECRET_KEY`, and database URLs through your deployment
configuration. Keep `INSTALLED_APPS` in Python or provide its JSON environment value.
The generated `config/asgi.py` sets a default settings-module environment variable but
explicitly loads `config.settings`; changing the environment variable alone does not
switch that explicit load. Update the ASGI and Aerich entry points together if you
use separate production settings modules.

## Start Uvicorn directly

From the project root:

```bash
uvicorn config.asgi:app --host 0.0.0.0 --port 8000
```

Use this instead of `fapilot runserver`, which always enables reload. Configure your
process supervisor to restart failed processes and allow graceful shutdown. Enable
ASGI lifespan so database startup and cleanup occur. If you add multiple workers,
each has separate connections, signal receivers, background tasks, and WebSocket hubs;
Fapilot does not coordinate them across processes.

## Migrations as a release step

Initialize new databases using the [database guide](databases.md). For an already
initialized environment, apply committed migrations once per affected group before
starting the new application version:

```bash
fapilot migrate --app products
fapilot migrate --app reporting
```

Do not generate new migrations during production startup or rely on debug schema
creation. Review schema changes, backups, and recovery before applying them. Test
changes against the same database engine used in deployment. The default database
also stores migration metadata for other connection groups.

## Container baseline

The scaffold's Dockerfile copies the entire directory and installs Fapilot from the
package index. Add a `.dockerignore` so environment files, databases, virtual environments,
and repository metadata are excluded from the build context:

```text
.env
.env.*
.venv/
.git/
__pycache__/
*.sqlite3
.pytest_cache/
.ruff_cache/
```

For a deployment using a tested `requirements.lock` generated by your dependency
workflow, a starting Dockerfile is:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.lock .
RUN pip install --no-cache-dir -r requirements.lock
COPY . .
RUN useradd --create-home appuser && chown -R appuser:appuser /app
USER appuser
CMD ["uvicorn", "config.asgi:app", "--host", "0.0.0.0", "--port", "8000"]
```

This example assumes that lock file already exists and contains Fapilot plus application
dependencies. Supply secrets at runtime. For SQLite, mount persistent writable storage
and use an absolute database path; a database in the container filesystem is not a
backup or persistent deployment strategy.

## Generated Compose file

`docker-compose.yml` defines only a PostgreSQL 16 service with development credentials
and host port 5432. It does not include an app service, named volume, migration job,
or automatic database URL configuration. `docker compose up -d postgres` starts that
service; it does not move the app away from SQLite. Set the application's URL yourself.
The database hostname is normally `localhost` for a host-run app and `postgres` for
an app service on the same Compose network. Replace development credentials and add
appropriate persistent storage before treating it as an operational database.

## HTTP and realtime operation

Terminate HTTPS at your deployment ingress or configure it for the server. Set CORS
origins explicitly. If enforcing hosts, install host middleware; `ALLOWED_HOSTS` alone
does not do it. SSE endpoints need proxy streaming/buffering configuration; WebSockets
need upgrade support. Authentication on those endpoints remains application code.

## Logs and health

Fapilot does not call `logging.config.dictConfig` for `LOGGING` or load
`config/logging.py` automatically. Apply your logging configuration explicitly in the
entry point. Avoid logging settings objects, database URLs, passwords, or bearer tokens.

Add a liveness endpoint explicitly, for example in `config/asgi.py` after app creation:

```python
# app is the FastAPI object created earlier in this file.
# @app.get("/health/live", include_in_schema=False)
# async def live():
#     return {"status": "ok"}
```

A liveness response is not proof that every database is healthy. Implement readiness
checks for the dependencies your app requires. Monitor connection failures, migration
failures, task exceptions, and failed lifecycle receivers. There is no built-in metrics
exporter, tracing setup, or durable task monitor.
